Controller and Keyboard Setup

Getting the right input working in a browser game

Input is the most common reason a browser game feels broken. The game is running, the graphics are fine, but the character will not move. Almost always the cause is focus, a browser shortcut, or a controller the browser cannot see.

This guide explains how browser input actually works, how to connect a controller, and how to fix the specific problems players run into most.

1. How browser games read input

Browser games do not talk to your operating system directly. They receive events from the browser, which means three things:

  • The game must have focus. If you clicked a browser toolbar, an ad or a chat window, your keystrokes go there instead of the game.
  • Browser and operating-system shortcuts take priority. Alt+Tab, Command+Tab, F11 and similar combinations will never reach a game.
  • Controllers are exposed through the browser's Gamepad API. If the browser does not detect the device, the game cannot use it.

If input stops working mid-game, click once inside the game area. That restores focus without reloading.

2. Keyboard: the reliable default

A wired or built-in keyboard is the most dependable way to play. It needs no drivers, no pairing and no browser permission. Before blaming a game, check these common issues:

  • Num Lock and Caps Lock — games that use arrow keys or letter keys can behave oddly if these are toggled. Some games use the numeric keypad, which does nothing while Num Lock is off.
  • Keyboard layout — games are usually written for a US layout. On AZERTY, QWERTZ or Dvorak layouts, WASD may not sit where the game expects. Many games also support arrow keys, which are layout-independent.
  • Stuck modifier keys — if Shift or Control appears to be held down, press it twice. Operating systems sometimes latch modifiers after a shortcut.
  • Hardware key rollover — cheap keyboards may drop a key when several are pressed at once. If sprinting and turning at the same time fails, that is a keyboard limitation, not a game bug.

3. Connecting a controller

Most modern browsers support standard gamepads through the Gamepad API. Support is best on Chrome, Edge and Firefox; Safari support exists but is less consistent.

Wired controllers

Plug the controller in, then reload the game page. Browsers usually only register a gamepad on page load. A controller connected after the game starts may not appear until you refresh.

Bluetooth controllers

Pair the controller with your operating system first, not with the browser. Once the system sees it as an input device, reload the game. On Windows, the controller should appear under Settings → Bluetooth & devices. On macOS, check System Settings → Bluetooth. On Linux, most controllers appear as an evdev device automatically.

PlayStation, Xbox and Switch controllers

Xbox controllers use XInput on Windows and are the most consistent choice. PlayStation controllers work through the browser's standard mapping, but button labels may not match the game's prompts. Switch Pro controllers often work in the browser once paired, though the button order may differ. Whichever controller you use, the game must explicitly support gamepads; a keyboard-only game will ignore it.

4. When the browser does not see the controller

Use a browser gamepad tester page to confirm the device is detected. If the tester shows no device, the problem is below the browser. Check, in order:

  • The cable or Bluetooth pairing.
  • Whether another application has exclusive control of the controller. Steam, console emulators and some launchers hold the device open.
  • Whether the controller is in the wrong mode. Some third-party pads have a switch between XInput, DirectInput and Switch modes; browser games generally expect XInput.
  • Whether the page is focused. Gamepad input is delivered to the focused document.

If the tester detects the pad but the game does not respond, the game likely has no controller support. Check its controls section on the game page.

5. Reducing input lag

Input lag is the delay between pressing a button and seeing the result. On a browser game it comes from four places: display latency, browser rendering, network latency and the game's own code.

  • Use a monitor's game mode if it has one. It disables post-processing that adds tens of milliseconds.
  • Close extra tabs so the browser is not competing for CPU.
  • Prefer a wired connection for online games; Wi-Fi adds variable latency that no input setting can remove.
  • Disable browser zoom. Non-100% zoom forces extra scaling work on every frame.

For single-player games, most remaining latency is display and rendering. For online games, network distance usually dominates, and nothing on your keyboard changes that.

6. Accessibility and alternative input

Browser games inherit browser accessibility support. If you use a switch device, an on-screen keyboard or voice control, those tools send ordinary key events if configured to emulate a keyboard. Games that support arrow keys are usually the easiest to drive this way because arrows map cleanly to directional switches.

Games that require precise mouse aim are harder to adapt. Some players use a trackball or a controller with gyro aiming; others rely on the game's own difficulty or assist options. 7. Quick checklist

  • Click inside the game before pressing keys.
  • Reload after connecting a controller.
  • Close applications that may hold the controller.
  • Check Caps Lock, Num Lock and your keyboard layout.
  • Try a second browser to separate game problems from browser problems.
  • Confirm the game lists the control scheme you are trying to use.
