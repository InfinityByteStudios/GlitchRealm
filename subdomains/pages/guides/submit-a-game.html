Submit a Game to GlitchRealm

What to prepare, what we review and what happens after approval

GlitchRealm is a curated library, not an open upload site. Every game is reviewed by a person before it appears in the catalogue. That review is short, but it is real: we check that the game runs, that it is yours to publish, and that a visitor can understand what they are about to play.

This guide explains exactly what we look at so you can prepare a submission that passes the first time.

1. What kinds of games we accept

We accept browser games that run from a URL without an install step. In practice that means HTML5, JavaScript and WebGL games hosted on your own domain or a static host.

  • Original games you built or have the rights to publish.
  • Playable in a modern browser — Chrome, Firefox, Safari or Edge, on desktop or mobile.
  • Free to play, or with a free, clearly playable core.
  • Complete enough to play — a prototype is fine if it has a real loop and the controls work.

We do not accept game portals, link collections, games that require a separate paid download, or pages whose main purpose is advertising.

2. What to prepare

A complete submission includes:

  • The playable URL — the page that opens the game directly. Use HTTPS.
  • A title — the name players will see. Keep it under about 40 characters.
  • A short description — one or two sentences, roughly 80–200 characters, explaining what the player does.
  • A long description — several paragraphs covering the setting, the loop, modes, progression and what makes the game different. This becomes the “About This Game” section.
  • How to play — controls, objective, win and lose conditions, and any systems a new player must understand.
  • Tags — three to six genres or mechanics, such as “puzzle”, “tower defence” or “incremental”.
  • A cover image — landscape, at least 1280×720, with the game's title readable at small sizes.
  • Screenshots — optional but strongly recommended. Two to six images showing actual gameplay.

Write the description yourself. Copy that reads like marketing filler is the most common reason a submission needs a second round.

3. Technical requirements

  • The game must load without a build step or a local server on the player's machine.
  • It must run over HTTPS. Mixed-content requests are blocked by browsers and will break parts of the game.
  • It should not depend on a plugin, a desktop app or a specific browser engine.
  • If it needs sound, the game should handle the browser's audio-unlock rule by starting audio after the first click.
  • If it stores progress, say where: local storage, your own account system, or nowhere.
  • If it has an account system, the sign-up and privacy flow must be yours to operate, and it must be described accurately.

Before submitting, test the game in a private window with no extensions, and test it once on a phone. Both catch problems that are invisible on a developer machine.

4. Rights and content rules

You must own the game or have written permission from the rights holder. That includes the code, art, audio and any trademarks. Fan games built on someone else's intellectual property cannot be published without that permission.

We do not publish games that contain hateful content, sexual content involving minors, targeted harassment, malware, or deceptive advertising. Games that collect personal data must disclose what they collect and link to their own privacy policy.

The full rules are in the submission policy and the developer agreement. By submitting, you confirm that you have read them.

5. How review works

Submissions arrive through the official submission form. A reviewer opens the game, plays long enough to understand the loop, and checks the listing against the submission.

There are three possible outcomes:

  • Approved — the game is published and gets a permanent page on GlitchRealm.
  • Changes requested — we explain what needs fixing, usually missing description, broken mobile layout or unclear controls. You can resubmit.
  • Declined — the game falls outside the content rules or the rights cannot be verified.

Review time depends on the queue. Most submissions are reviewed within a few days. There is no fee, and submitting does not transfer ownership of your game.

6. After approval

Approved games get a canonical page at /game/<slug>/ with a title, description, controls, FAQ, screenshots and structured data. The page is static HTML, so it loads quickly and can be read by search engines and AI assistants.

To give the page the best chance of being indexed, make sure the long description and how-to-play sections are substantial. Pages with only a short blurb are published but kept out of the sitemap until the copy is filled in.

If you update the game later, send the changes through the same contact route. We can update the listing without changing its URL, and the URL stays stable if the title changes.

7. Common reasons a submission is delayed

  • The playable URL opens a landing page instead of the game.
  • The description repeats the title without explaining the loop.
  • Controls are missing or do not match the game.
  • The cover image has unreadable text at card size.
  • The game breaks on mobile or in a fresh browser profile.
  • The rights holder is unclear, or the game uses assets the submitter does not own.
